# YouTrube 5.1 — исправления после проверки

Готовое приложение — `index.html`. Обновление закрывает три подтверждённые проблемы из отчёта `audit-2026-10-10.md`.

## Что исправлено

1. **Защита резервных копий.** Проверяются служебные ID уведомлений и комментариев, внутренние ссылки и структура данных. Значения в HTML-атрибутах дополнительно экранируются. Небезопасное сохранение отклоняется до загрузки; исходные данные в хранилище сохраняются.
2. **Защита прогресса между вкладками.** На одном адресе работает одна вкладка симулятора. Остальные ожидают и после закрытия активной вкладки загружают последнее сохранение. Основной механизм — Web Locks; резервный использует атомарные транзакции IndexedDB. После аварийного закрытия в резервном режиме ожидание составляет до 8 секунд. Изменение сохранения старой версией останавливает устаревшую вкладку и оставляет возможность экспортировать её состояние.
3. **Равномерный расчёт аудитории.** Убрано завышение минимального времени для возвращающихся зрителей. Обучение алгоритма учитывает фактически прошедшее время и объём показов. В четырёх суточных сценариях разница прироста подписчиков между обновлениями каждые 2 секунды и обработкой суток офлайн составляет 0,21–0,51% для Shorts и 1,22% для обычного видео. Полной математической идентичности модель с адаптивными шагами не гарантирует.

## Проверка и сохранения

Пройдены 463 автоматические проверки приложения и 35 проверок миграции пользовательской копии. Проверены импорт, несколько вкладок, смена владельца сохранения, отказ записи, миграция, календарь, продвижение, сообщество, плейлисты и виртуальная монетизация. Подробные результаты находятся в `test-results-v51.json`; новые регрессионные сценарии — в `tests-v51.cjs`.

Нагрузочный сценарий с 1 000 публикаций и 30 днями офлайн прошёл за 28,7 секунды на этой машине. Это тяжёлый сценарий: обработка больших историй всё ещё может занимать заметное время.

На резервной копии пользователя проверено сохранение всех трёх собственных публикаций, их показателей, дат и паузы. После установки 5.1 страница обновлена по прежнему адресу; повторный экспорт подтвердил сохранение всех 231 публикаций, показателей собственных видео, подписчиков и паузы. Ошибок в консоли при запуске не обнаружено. Старые данные версии 3.1 мигрируют в текущую структуру; новые показатели монетизации начинают накапливаться после обновления без начисления дохода за старые просмотры.

Обновляйте HTML по прежнему адресу в том же браузере. При смене домена, порта или браузера переносите сохранение через экспорт и импорт. Существующие localStorage и IndexedDB используются без сброса.

## Воспроизводимая сборка

Из корня проекта: `python3 work/install_v5.py`. Сборщик применяет обновление `work/apply_v51.py`; модули безопасности, хранения и координации вкладок находятся рядом с ним. Приложение остаётся автономным HTML без внешних скриптов.
